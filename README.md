⭐ *Este es mi repositorio oficial donde documento y presento el desarrollo completo de **Lumina**, un proyecto integral enfocado en una aplicación de gestión de tareas y organización personal. Este desarrollo fue realizado como parte de mi cursada en la materia **Gestión de Proyectos**.* 🎯

---

## 📌 1. Resumen y Estado del Proyecto

Lumina fue concebida y llevada a producción para optimizar la productividad y organización diaria de los usuarios. El ciclo de vida del proyecto ha concluido de manera exitosa con la entrega formal al cliente (*Gestión ProActiva S.A.*) el **10/11/2025**.

### 📦 Entregables Clave
* 💻 **Aplicación Lumina operativa:** Desplegada y publicada en entorno productivo (web/app).
* 📖 **Manual de usuario:** Documentación en PDF y versión accesible integrada dentro de la plataforma.
* ⚙️ **Manual técnico:** Transferido al área técnica, abarcando backend, API y bases de datos.
* 🔑 **Accesos y Seguridad:** Gestión de usuarios administradores, tokens de API y respaldos (backups).
* 🎓 **Capacitaciones:** Guías rápidas y grabaciones de las sesiones para los usuarios administradores.
* 🔔 **Sistema de notificaciones:** Documentación completa de flujos, reglas y estados configurados.

---

## 🛠️ 2. Tecnologías y Enfoque de Gestión

Durante el ciclo de desarrollo e implementación, estructuré el proyecto aplicando metodologías ágiles y estándares de la industria:
* 🗂️ **Gestión Ágil:** Uso de reuniones breves semanales (*stand-ups*) para evitar bloqueos y asegurar una comunicación fluida.
* 🔍 **Control de Calidad (QA):** Pruebas de flujos dinámicos, recordatorios y tareas recurrentes.
* 🛠️ **Arquitectura modular:** Diseño enfocado en la escalabilidad y la integración robusta de APIs externas y sistemas de notificaciones.

---

## 📋 3. Evaluación y Lecciones Aprendidas

Como parte de la gestión profesional del proyecto, realicé un análisis post-mortem (*Closing & Lessons Learned*):

| Área | Qué pasó | Lección Aprendida | Recomendación Implementada |
| :--- | :--- | :--- | :--- |
| **Desarrollo** | La integración del módulo de notificaciones tomó más tiempo del previsto. | Las integraciones con APIs externas deben planificarse con mayor margen. | Incorporar un búfer del 20% en tareas críticas de desarrollo. |
| **QA** | Se subestimó el tiempo destinado a pruebas de recordatorios y tareas recurrentes. | El aseguramiento de calidad requiere ciclos más amplios para flujos dinámicos. | Incluir pruebas automatizadas básicas desde etapas tempranas. |
| **Comunicación** | Las reuniones breves semanales funcionaron de manera muy efectiva. | La comunicación ágil previene drásticamente el retrabajo y los bloqueos. | Mantener dinámicas de comunicación cortas y herramientas ágiles. |
